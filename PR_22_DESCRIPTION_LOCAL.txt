PR 标题
feat(site): 增加站点 SEO、字符替换、自定义 URL 与伪静态解析基础能力

关联 Issue
Fixes #22

背景说明
Issue #22 提到希望支持站点配置、SEO、字符替换、URL 自定义、伪静态等能力。
本次先补齐后端可复用的基础能力（工具函数 + 单测），为后续控制器/页面配置接入提供稳定底座。

本次功能代码改动
新增文件：
- library/libUtils/site_features.go
- library/libUtils/site_features_test.go

1) SEO 元信息构建
- 新增 SiteSEOOptions、SiteSEOMeta
- 新增 BuildSEOMeta
- 支持“页面值优先、站点默认兜底”的 title/keywords/description 生成策略
- 支持站点名拼接（可配置分隔符）

2) 字符替换规则
- 新增 ReplacementRule
- 新增 ApplyReplacementRules
- 按规则顺序执行替换，便于后续在内容渲染阶段统一调用

3) 自定义 URL 生成
- 新增 URLRewriteOptions
- 新增 BuildCustomContentURL
- 支持 prefix/suffix 方式生成内容访问路径（如 /article/slug.html）

4) 伪静态 URL 解析
- 新增 ParsePseudoStaticContentURL
- 可将伪静态路径反解析为 slug，便于后续路由与内容查询层接入

兼容性与风险
- 本次为新增工具函数，不影响现有接口行为，默认兼容
- 风险较低，主要在后续接入业务时需统一规则优先级

后续建议
- 在 CMS/内容模块接入站点配置持久化（数据库）
- 在渲染或 API 输出层统一调用 SEO 与替换逻辑
- 在路由层引入伪静态入口并对接 ParsePseudoStaticContentURL
